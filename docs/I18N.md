# Arabic support: audit and plan

Goal: a language switch (English / العربية) in the trainee app's Preferences and in the coach website's sidebar, defaulting to the device or browser language, with translations good enough that a Saudi lifter or coach never feels they are reading a machine. This is a multi-week track; each phase ships behind the switch so English users see no change.

## What exists today

| Surface | User-facing strings (approx.) | Notes |
| --- | --- | --- |
| Trainee app (`mobile/src`) | ~450 | Largest: workout (73), coach (64), weight (61), conversation (61), train (45) |
| Coach website + web tracker (`app/`) | ~470 | `coaching-ui.tsx` alone ~195 |
| API error messages (`lib/*-server.ts`) | ~70 | Returned as English text and shown verbatim |
| Dates | `dateLabel` and 5 direct `toLocaleDateString('en-GB')` calls | Hard-coded locale |
| Numbers | ~40 `toLocaleString()` calls | Follow the runtime locale already |
| Layout direction | ~30 physical left/right styles in the app, ~66 in the two stylesheets | Need logical properties for RTL |
| Typeface | Outfit (Latin only) | Needs an Arabic companion |

No i18n library is installed on either surface. The app has `expo-font`; neither has a locale detector.

## Approach

1. **One dictionary, two runtimes.** `lib/i18n/en.ts` is the source of truth (typed keys, ICU-style placeholders like `{count}`), `lib/i18n/ar.ts` mirrors it. A tiny `t(key, vars)` plus a `useLocale()` provider on each surface; no heavy library. Missing Arabic keys fall back to English and are listed by a unit test so nothing ships half-translated by accident.
2. **Preference.** App: Preferences sheet gains "Language / اللغة" (System, English, العربية) stored in AsyncStorage. Website: a control under Appearance in the coach sidebar and in the tracker, stored in `localStorage` and mirrored to a cookie so the server can render `<html lang dir>` correctly on first paint. Default: device locale on the app, `Accept-Language` on the web.
3. **Right-to-left.** Web: set `dir="rtl"` on `<html>` and convert physical CSS (`margin-left`, `left:`, `text-align: left`) to logical properties (`margin-inline-start`, `inset-inline-start`, `text-align: start`). App: `I18nManager.forceRTL` needs an app restart on native; on web React Native maps `start`/`end` styles automatically, so the app code moves to `marginStart`/`marginEnd`/`textAlign: 'start'` as well. Icons that imply direction (chevrons, arrows) flip; charts and numbers stay LTR.
4. **Typeface.** Outfit has no Arabic glyphs. Pair it with **IBM Plex Sans Arabic** (same weights we use, geometric, excellent hinting, Google Fonts, `@expo-google-fonts/ibm-plex-sans-arabic`). The wordmark stays as it is. Arabic display sizes get slightly larger line-height (1.35) and no negative letter-spacing.
5. **Dates and numbers.** Route every date through one formatter that uses `Intl.DateTimeFormat` with the active locale and the Gregorian calendar explicitly (`ar-SA` defaults to Umm al-Qura), and one number formatter. Keep Western digits for weights, reps and steps (what Saudi fitness apps do) via the `nu-latn` extension; this is a single switch if the team prefers Arabic-Indic digits.
6. **Server messages.** The API returns error codes alongside the English text; clients translate the code. Coach-written content (notes, messages, program titles) is never translated.
7. **Quality.** Translation is written by hand in Modern Standard Arabic with Gulf-neutral gym vocabulary, then reviewed by a native speaker on the team before each phase merges. The e2e suite gets an Arabic run for the core flows so layout regressions are caught.

## Decisions (13 Sep 2026)

- Numbers, dates and API error messages stay as they are; only interface text is translated.
- Phase 1 shipped: dictionaries in `lib/i18n/`, language switch in the app's Preferences and the coach sidebar, `<html lang dir>` set before paint, IBM Plex Sans Arabic loaded on both surfaces, and the shell, Train tab, You tab, steps and assigned program translated. Remaining screens follow.

## Phases

1. **Foundation** (1 PR): dictionary + `t()` + providers, language preference on both surfaces, `<html lang dir>`, Arabic font loading, date/number formatters, unit test for missing keys. Translate navigation, tab bar, Preferences and the Train tab. RTL pass on the app shell, tab bar and cards.
2. **Trainee app** (2 PRs): Workout, Weight, You, My coach, conversation, steps, sheets and notices. RTL pass on chat bubbles and sheets.
3. **Coach website** (2 PRs): sidebar, clients list, client detail tabs, program editor, templates, profile & packages, Marketplace. Logical CSS across both stylesheets.
4. **Server and QA** (1 PR): error codes, Arabic e2e run, native-speaker review, screenshots in both languages in the changelog.

Each phase: `npm run verify`, e2e in both languages, and a screenshot comparison in the PR.
